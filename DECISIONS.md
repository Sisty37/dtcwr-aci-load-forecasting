## Notes for the paper

- D6 is itself a finding: CUSUM thresholds calibrated for independent data are far too low for h-step forecast residuals.
- D8 failure mode: with a high AR(1) coefficient (Elec2 h=48, phi near the 0.95 cap), prewhitening shrinks a persistent level shift in the detector input by sqrt((1-phi)/(1+phi)) (about 0.16 at phi = 0.95), below the CUSUM reference k, so the shift is never accumulated. This is the known loss of power of residual-based CUSUM for step changes under strong positive autocorrelation. Report it; do not tune around it on test data.
- With H calibrated, DTCW-R on un-shifted validation streams behaves almost like its long window (few alarms). Its earlier advantage in local coverage came from false alarms acting as a short window. Any claimed advantage must come from the injected-shift experiments.
- Replication status (Section 7.2): Conformal PID (quantile and integrator) and ECI / ECI-cutoff reproduce the repositories' quantile sequences to machine precision (random streams, Elec2 P-pub, ECI's change-point data). DtACI tracks the best expert of its grid after a shift. ROCP picks an interior window under local stationarity and a large window on i.i.d. data. DriftOCP lowers cumulative coverage error under piecewise-constant variance. All pass the i.i.d. gate (0.89-0.91) at h = 1 and 24.
- To check in the Table C batch (do not claim yet): with the code form and proportional lr, ECI's intervals were about as wide as the plain quantile tracker with the same lr on the authors' change-point data. ECI's Table 3 compares against OGD with an absolute (not range-scaled) lr grid, which may explain part of the reported width gap.
- ECI's Elec2 config also uses only the first 2,000 rows (`tests/datasets.py`, `df[:2000]`), same as Conformal PID (D2). Its cached AR forecasts differ from the PID repo's by at most 0.0036 (refit noise); Table C uses each repo's own cached forecasts when reproducing that repo's numbers.
